**如实标注两点环境事实**：
1. `pip install -r requirements.txt` 从 PyPI 默认源装到的是 CUDA 版 torch（`2.14.0+cu130`，含 nvidia 依赖，约 6.8 GB）；
   本复现**始终用 `--cpu` 启动产品**，全程不使用 GPU，所以这个体积差异不影响结论。
2. 浏览器出网被限制成"外网域名不可解析、回环不受影响"（`--host-resolver-rules`），
   等价于语料里另一次复现所用的 `docker run --network none`。它不碰被审路径：产品自己的前端、
   自己的路由、自己的写盘都照常执行；被挡掉的只有 civitai 这个第三方查询。

## 2. 一键复现（3 条命令）

在 WSL 里跑（首次需要 `setup_env.sh`，约 20–30 分钟，主要是 torch 下载）：

```bash
# 1) 准备环境（幂等，可重复执行）
bash poc/setup_env.sh

# 2) 把复现件部署到复现根目录（换机器/改过脚本后都要重跑这一步）
bash poc/deploy_kit.sh

# 3) 一条命令跑完整链路：造样本 → 布控 → 起真产品 → 真浏览器驱动 → 真重启 → 校验
bash ~/cve_repro_modelspec/poc/run_repro.sh
```

`run_repro.sh` 的退出码就是结论，最后会打印：

```
xss_confirmed        : True
payload_ran          : True
staged_overwrite     : True
negative_control     : True
control_handler_alive: True
restart              : EXECUTED
OVERALL              : D4_end_to_end_safe
```

> 若只从 Windows 侧调用：`wsl -d kali-linux -e bash "/mnt/e/Reproduce/<本目录>/poc/setup_env.sh"`
> 等价的绝对路径写法均可；`setup_env.sh` / `deploy_kit.sh` 支持从任意 cwd 执行。

## 4. 重新截图

改过脚本或想重拍时（`shot_scenario.json` 会把状态重置，可直接重跑）：

```powershell
# 注意：必须先部署，否则 WSL 侧跑的还是旧脚本
wsl -d kali-linux -e bash "/mnt/e/Reproduce/pythongosssss-ComfyUI-Custom-Scripts_modelspec_staged_rce_2026-09-24/poc/deploy_kit.sh"

powershell -NoProfile -ExecutionPolicy Bypass -File poc\real_terminal_shot.ps1 `
    -Scenario poc\shot_scenario.json -OutDir screenshots
```

采集依赖一个可交互桌面会话（要开真实终端窗口）。跑完请**逐张打开核对**：窗口完整、无遮挡、
无输入法候选框、输出完整、提示符已回到待输入状态。

关于 `real_terminal_shot.ps1`（相对 skill 原版只改了两处等待时间，都是踩坑后加的，**必须保持 UTF-8 with BOM**）：

- 粘贴到回车之间的等待 250 ms → **700 ms**：bracketed paste 的结束标记会和回车抢跑，bash 会吞掉或
  重复命令的最后一个字符（实测出现过 `bash stop_product.s`、`$VICTIM_INITT`）。
- 窗口就绪后的等待 500 ms → **2500 ms**：控制台还没初始化完就发第一条命令，`wsl -d kali-linux`
  会被丢掉，整场会在 PowerShell 里跑而不是在 Linux 里（实测踩过一整轮）。

另外：`shot_scenario.json` 把 `wsl -d kali-linux` 放在 `steps` 第一步（而不是 `initCommands`），
前面留 4 秒等待，理由同上。

**两个哈希是跨运行稳定的**：描述字符串与 `staged_init.py`。**`.safetensors` 文件不是**——
writer 从哈希表序列化 `__metadata__`，键序在进程间不稳定，所以每次构建的文件哈希都不同
（上一次复现是 `7f4a8b12…` / `cdf34aea…`，同一份 payload）。跨运行比对请比 payload，不要比文件哈希。

## 7. 复现边界（诚实清单）

- **终点是不可逆效果的替身**：被覆盖的 initializer 只写一个 marker 文件并注册零个节点，
  没有携带任何武器化 payload；因此评级口径是"真实栈端到端，终点效果用惰性金丝雀替代"。
- **未证明**：civitai 分支（联网环境下渲染的是 civitai 的字符串，是同构的第二个入口）；
  同族的另外三个 `innerHTML` sink（`modelInfoDialog.js:116`、`modelInfo.js:292`、
  `autocompleter.js:159`）只做了源码同构判断，没有实跑。
- **受害者包是替身**：`Victim-Demo-Pack` 是一个真实安装、被真产品启动时真实 import 的普通节点包，
  代表受害者实际装的任意节点包；被利用的写原语与具体是哪个包无关。
- **没有越权、没有目录穿越**：写入落在 `custom_nodes/` 内，用的是 ComfyUI 进程自身权限；
  写路由的源路径 `../` 穿越会被 400 拒绝。
- **踩过的坑值得写下来**：第一版 payload 把模板字符串当对象字面量的键名（`` {`method`:'POST'} ``），
  V8 报 `SyntaxError: Unexpected template string`，内联处理器**根本没编译**，浏览器表现成
  `img.onerror === null` —— 与"产品拦住了 XSS"在观测上完全一样。是页内 `new Function()` 编译诊断
  加同页手工对照处理器把它和真正的缓解区分开的。语料里另一次复现栽在同类问题上（payload 正文里的撇号）。
