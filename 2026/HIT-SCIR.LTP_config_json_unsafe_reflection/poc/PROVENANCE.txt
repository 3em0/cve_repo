Two stacks are built from this kit, because they behave differently:

  (A) RELEASED stack      -> image `ltp-poc:released`  (Dockerfile)
      pip install ltp==4.2.14 ltp_core==0.1.4 ltp_extension==0.1.13
      This is what `pip install ltp` resolves to today. ltp_core 0.1.4 was
      uploaded to PyPI on 2023-01-04 and still contains the re-export in
      ltp_core/models/utils/__init__.py, so ltp/nerual.py really reaches the
      unsafe instantiate() function.  ==> VULNERABLE, exploited by run_poc.py.

  (B) PINNED SOURCE stack -> image `ltp-poc:pinned`    (Dockerfile.pinned)
      Built from https://codeload.github.com/HIT-SCIR/ltp/tar.gz/1f042d48...
      At this commit the file ltp_core/models/utils/__init__.py is EMPTY
      (it was emptied by commit 58995052 "ruff", 2023-06-27), so
      `from ltp_core.models.utils import instantiate` binds the *module*
      instead of the function and the neural path dies with
        TypeError: 'module' object is not callable
      before find_callable() is ever entered.  ==> NOT REACHABLE through
      ltp.LTP(model_dir); recorded as an honest boundary, not as a mitigation.
