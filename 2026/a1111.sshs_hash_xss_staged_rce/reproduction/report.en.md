# a1111.sshs_hash_xss_staged_rce — end-to-end validation

**Product:** AUTOMATIC1111/stable-diffusion-webui **v1.10.1**,
`82a973c04367123ae98bd9abdf80d9eda9b910e2` (verified in-container).
**Host:** `.37` · **Image:** `mbe2e/v/a1111.sshs_hash_xss_staged_rce:r1` on
`mbe2e/prod:a1111-82a973c0-browser` · **Run time network:** `--network none`
(Chromium and the WebUI share one network namespace that has only loopback).

## Attacker capability

One LoRA package the victim unpacks — or `git clone`s, which is how every
Hugging Face model repo is obtained — into `models/Lora/`:

```
mbe2e_lora/
    evil.safetensors          valid safetensors; __metadata__.sshs_model_hash carries the payload
    install.py                stage 1
    scripts/mbe2e_stage2.py   stage 2
    .git/                     the package is a git checkout, as it is after `git clone`
```

## Victim action

Start the WebUI and open `http://127.0.0.1:7860/`. Nothing else. The
extra-networks HTML for every registered page is generated by
`interface.load` (`modules/ui_extra_networks.py:788`), so the LoRA card — and
with it the payload — is in the DOM before the user clicks anything.

## The chain

1. **Metadata is read verbatim.** `modules/sd_models.py:285-309`
   `read_metadata_from_safetensors` copies every `__metadata__` entry; a value
   that does not begin with `{` is returned unchanged.
2. **A string becomes "the model hash".** `extensions-builtin/Lora/network.py:50-57`
   `set_hash(metadata.get('sshs_model_hash') or …)` — no hex, length or charset
   check. Everything a hash is supposed to be is assumed, nothing is verified.
3. **It is put on the card.** `extensions-builtin/Lora/ui_extra_networks_lora.py:27-29`
   appends the full hash to `search_terms`.
4. **It is interpolated unescaped.** `modules/ui_extra_networks.py:312-320`

   ```python
   search_term_template = "<span class='hidden {class}'>{search_term}</span>"
   ```

   Every sibling field on the same card is escaped — `sort_keys` at :306 uses
   `html.escape`, `description` at :328 uses `html.escape`. `search_term` is the
   one that is not. Being inside a `hidden` span has no security effect: parsed
   event-handler content still runs.
5. **Same-origin script runs**, then drives the product's own hidden installer
   controls (`modules/ui_extensions.py:603-604`) — the exact pair A1111's own
   `javascript/extensions.js:47-55` uses for its extension index.
6. **Stage 1 — host code execution.** `modules/ui_extensions.py:344-394`
   `install_extension_from_url` git-clones the attacker-named path into
   `extensions/`, then `modules/launch_utils.py:228-237` runs the package's
   `install.py` in a Python subprocess. Canary
   `/out/pwned_by_a1111_sshs_stage1`.
7. **The product restarts itself.** The same script presses "Apply and restart
   UI" → `modules/ui_extensions.py:26-56` → `modules/restart.py` `restart_program()`
   → `os._exit(0)`; `webui.sh` re-execs because it exported `SD_WEBUI_RESTART`.
   **No human is in this loop** — that is why the launcher is `webui.sh` and not
   `launch.py`.
8. **Stage 2 — across the import boundary.** On the new process
   `modules/scripts.py` `load_scripts()` imports
   `extensions/mbe2e_lora/scripts/mbe2e_stage2.py`. Canary
   `/out/pwned_by_a1111_sshs_stage2`.

The DATA→CONTROL crossing is step 2→4: a field the safetensors parser correctly
returned as an opaque string is used as HTML without being re-validated for that
new purpose. Steps 5–8 are the product's own documented features being used by
whoever holds the origin.

### `INSTALL_UNCONFIRMED` is a real finding, not harness noise

The payload originally waited for A1111's own "Installed into ..." confirmation
before pressing restart, and it never arrived — while the extension had in fact
been cloned and its `install.py` had already run. The reason is in
`modules/ui_extensions.py`: `install_extension_from_index` calls
`install_extension_from_url` (clone + `run_extension_installer`) and only then
calls `refresh_available_extensions_from_data`, which raises when no extension
index has been loaded. The exception aborts the Gradio call, so the UI reports
nothing — **but the clone and the code execution are not rolled back.** The
installer's side effects outlive the failure of the call that produced them. The
payload now proceeds on a bounded timeout, which is what an attacker would do.

### Things that had to be right, and were not obvious

- `repair_config`-style surprises exist on this path too: A1111 keys its
  safetensors-metadata cache and its `available_networks` dict on
  `os.path.basename(filename)` (`extensions-builtin/Lora/networks.py`), so a
  negative package whose file is also called `evil.safetensors` silently serves
  the benign metadata to the positive phase. The two packages therefore use
  different file names.
- Two product lifetimes in one container need a hard barrier: the second phase
  must not start until nothing is listening on 7860, or it quietly talks to the
  previous process.

## Verification boundary — what is NOT proven

- **The extension installer is a documented executable feature.** No CVE-style
  claim is made about it. The new root is that *model metadata* acquires
  same-origin browser authority without consent.
- **Reachability of stage 1 depends on the launch mode.**
  `modules/shared_cmd_options.py:17-18` disables extension access when
  `--share`/`--listen`/`--server-name` is used without
  `--enable-insecure-extension-access`. The default localhost launch — the one
  used here and the overwhelmingly common one — leaves it enabled. Under
  `--listen` the XSS still executes; only stages 1 and 2 are blocked.
- **The package is a git checkout.** A1111's installer clones, so the payload
  package has to be clonable. That is the normal state of a model directory
  obtained with `git clone https://huggingface.co/...`, but a package delivered
  as a plain zip without `.git` would need a different second stage.
- `--skip-load-model-at-start` is used: no checkpoint is present and this root
  has nothing to do with checkpoint loading. It removes a pointless startup
  download attempt, nothing else.
- Both canaries are inert file writes inside the container. No persistence to the
  host, no network, no credential access.
